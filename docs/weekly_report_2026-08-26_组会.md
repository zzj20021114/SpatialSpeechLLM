# 项目周报：基于 Qwen3 的定向多任务语音理解大模型

> **组会报告 · 2026-08-26**
> 报告人：课题组成员 ｜ 项目：Spatial-OSUM / DirectedASR
> 核心：**自建编码器-解码器**实现"定向 ASR"（语音转录 + 声源左右判定），个人单卡可训练。

---

## 一、课题背景与目标

### 1.1 为什么做"定向语音理解"

多声道（空间）音频天然包含**声源方位**信息。现有语音理解大模型通常只处理单声道，
丢弃了空间线索。我们的目标是把**语音内容理解**与**声源方位感知**统一到一个模型中：

| 能力 | 来源思想 | 用途 |
|---|---|---|
| 多任务语音理解（ASR + 副语言属性） | OSUM | 转写、情感/风格/性别等 |
| 多声道声源定位 | Spatial-Omni | 声源方位、空间关系 |
| 大模型文本生成 | Qwen3 | 统一输出 |

**首期任务（左右定向 ASR）**：给定 4 通道 FOA 音频 →
输出 `语音转录 + 说话人方位（左/右）`。

### 1.2 为什么"自建编码器-解码器"而不是"封装大模型"

前期尝试"封装 Qwen3-Omni-30B（多模态大模型）"失败并放弃：
- 30B MoE 权重 bf16 ≈ 60GB，单张 32GB 卡连加载都 OOM；
- MoE 专家层非标准 `nn.Linear`，bitsandbytes 4-bit 无法量化；
- 个人/课题组无力训练 30B 级大模型。

**结论**：改为**自建编码器 + 可微调解码器**——
- 编码器完全自研（空间特征提取是**本项目的核心贡献**）；
- 解码器用公开 **Qwen3-8B** + LoRA 微调（~1.5 亿可训练参数）；
- **个人单卡（32GB）即可训练**（实测显存 17GB）。

## 二、整体架构

```
                     FOA 4 通道音频 (16 kHz, [W,Y,Z,X])
                                  │
        ┌─────────────────────────┴─────────────────────────┐
        │ 编码器（自建，~1 亿参数，可训练）                    │
        │                                                    │
        │  AudioFrontend: FOA → 7 通道特征图                 │
        │   (W/X/Y/Z 的 log-mel + 强度向量 IVx/IVy/IVz)       │
        │                    │                               │
        │  SpatialEncoder: 特征图 → token 序列 (12.5 Hz)      │
        │   (自写 Transformer + 相对位置编码)                 │
        │                    │                               │
        │  Projector: token → 解码器隐空间 (MLP→4096)        │
        └─────────────────────┬─────────────────────────────┘
                              │  masked_scatter 注入
        ┌─────────────────────┴─────────────────────────────┐
        │ 解码器：Qwen3-8B（公开文本 LLM，LoRA 微调）         │
        │  输入文本：<|speech|>*N \n {指令} \n {答案}        │
        │              （<|speech|> 位置填入编码器 token）    │
        └─────────────────────┬─────────────────────────────┘
                              ▼
                  输出：今天开会。 <方位> 左
```

### 2.1 各模块要点

**① AudioFrontend（FOA 前端，自研）**
- 输入 4 通道 FOA（DCASE 序 `[W,Y,Z,X]`），16 kHz；
- 逐通道 log-mel（128 维）+ 强度向量 `IV = Re(W̄·{X,Y,Z})` → 7 通道特征图；
- W 通道（全向）= 语音内容；XYZ + IV = 声源方向。

**② SpatialEncoder（空间/语音编码器，自研）**
- Conv2d patch 嵌入（频率折叠）→ 12.5 Hz token；
- 自写 pre-LN Transformer（含相对位置偏置）；
- 一个编码器同时承载**语音内容**（来自 W/IV）与**左右方位**（来自 X/Y/IV）。

**③ Projector**：MLP 把编码 token 投影到 Qwen3-8B 隐空间（4096）。

**④ Qwen3-8B 解码器 + LoRA**
- 公开 `Qwen/Qwen3-8B`（HuggingFace），LoRA 微调注意力与 FFN 投影；
- 文本中 `<|speech|>` 占位符展开 N 个 → 编码 token 嵌入 masked_scatter 填入。

## 三、定向 ASR 如何实现

### 3.1 任务定义（首期：左右二分类 + ASR）

- 输入：4 通道 FOA 语音（单说话人）
- 输出：`<转录内容> <方位> 左|右`
- 示例：`今天下午开会。 <方位> 左`

### 3.2 数据管线（全自动合成，无需人工标注方位）

```
语音语料(wav+txt)                    ── AISHELL-1（141,925 条）
   │  build_speech_manifest
   ▼
speech manifest {key, wav, txt}
   │  generate_synthetic_foa --leftright
   ▼
FOA wav + 方位标注 {side, azimuth, elevation}
   │  （SN3D 空间化：随机左右半区 45–135°/225–315°）
   ▼
QA jsonl {prompt, answer=“转录 <方位> 左”}
```

| 拆分 | 语音 | 合成 FOA | QA |
|---|---|---|---|
| train | 120,098 | 116,948 | ✅ |
| dev | 14,326 | 14,326 | ✅ |
| test | 7,176 | 7,176 | ✅ |

### 3.3 训练策略（融合 OSUM 的 ASR+X 思想）

| 阶段 | 内容 | 可训练参数 | 目的 |
|---|---|---|---|
| S0（可选） | 空间编码器 SELD 预训练 | 编码器 | 空间底座 |
| **S1** | 仅投影器 | 5M | 对齐编码 token 与 LLM 语义 |
| **S2** | 编码器 + LoRA + 投影器 | ~145M | **ASR+左右联合训练（核心）** |

- **ASR+X 原则**：每个训练样本的答案都含转录 → ASR 始终与定位联合优化；
- LoRA：`r=16, alpha=32`，目标 `q/k/v/o/gate/up/down`；
- 单卡 bf16：batch 2、grad_accum 4、显存 ~17GB。

### 3.4 推理与评估

- 推理：`<|speech|>*N + 指令` → Qwen3-8B 自回归生成；
- 评估 `dasr/evaluate.py`：
  - **side_accuracy**（左右判定准确率，首期核心）
  - CER/WER（转录字/词错误率）
  - 联合准确率（转录 CER≤阈值 且 左右正确）

## 六、关键结论

- **个人单卡可训练**：自建编码器（~1 亿） + Qwen3-8B LoRA（~5 千万），显存 17GB；
- **空间能力是自研贡献**：FOA 前端 + 空间编码器完全自建，可在 SELD/定向任务上持续迭代；
- **全链路打通**：数据合成 → 训练 → 推理 → 评估，代码独立原创、可发表；
- **风险**：8B 解码器单卡训练偏慢（全量 116K 需数十小时/epoch），建议后续多卡或减量优先出基线。
